# 💻 Посібник для розробників (Development Guide)

Цей документ описує стандарти написання коду, конвенції розробки, Git-процеси та процедури тестування для платформи **Sunflower Land Bot**.

---

## 🛠️ Налаштування локального оточення

### Необхідні інструменти:
1. **Node.js:** v20.x або вище (LTS рекомендовано).
2. **pnpm:** версія 8.x або 9.x (`npm install -g pnpm`).
3. **Python:** 3.10+ з встановленим пакетним менеджером pip (потрібен для локального компілювання/запуску Camoufox).
4. **Git:** для контролю версій.
5. **IDE:** Рекомендовано Visual Studio Code з плагінами:
   - ESLint
   - Prettier
   - Tailwind CSS IntelliSense
   - Error Lens

### Початкова ініціалізація проєкту:
```bash
# Клонування репозиторію
git clone https://github.com/Dimah98/DXDSF.git
cd DXDSF

# Встановлення всіх залежностей монорепозиторію
pnpm install

# Збірка спільних типів (обов'язково перед запуском)
pnpm --filter @sf/shared-types build

# Встановлення антидетект-браузера Camoufox
python -m pip install camoufox
python -m camoufox fetch
```

## 🏗️ Структура монорепозиторію

Проєкт використовує робочі простори (pnpm workspaces):
- `backend/` — серверний рушій Node.js, Express, Playwright.
- `frontend/` — клієнтський SPA інтерфейс React Flow, Vite.
- `packages/shared-types/` — спільні контракти типізації TypeScript.
- `sl-bot-remote/` — мобільний клієнт на Android (Kotlin).

## 📜 Стандарти кодування (Coding Standards)

### 1. TypeScript Strict Mode
- Уникайте використання типу `any`. Використовуйте сувору типізацію, дженерики або `unknown` з наступними type-guards (`isWSMessage`).
- Усі нові інтерфейси, що використовуються одночасно на фронтенді та бекенді, повинні додаватися до `@sf/shared-types`.

### 2. Обробка помилок
- **Заборонено:** мовчазні порожні блоки `.catch(() => {})` або `catch (_) {}`. Кожна помилка повинна бути або залогована через `logger.warn`/`logger.error`, або передана у вищий шар обробки.
- Використовуйте типізовані класи помилок з `src/errors/AppError.ts`:
  - `ValidationError` — для некоректних даних від користувача (HTTP 400).
  - `AuthenticationError` — проблеми авторизації (HTTP 401).
  - `NotFoundError` — проект або збереження не знайдено (HTTP 404).
  - `BrowserError` — збої Playwright, селекторів або падіння процесу Camoufox (HTTP 500).
  - `DatabaseError` — збої операцій з базою даних SQLite (HTTP 500).
- У маршрутах Express завжди передавайте неперехоплені помилки в `next(error)` для централізованої обробки.

### 3. Логування
- Використовуйте виключно модуль `logger` (`src/logger.ts`), а не прямий `console.log`.
- Завжди передавайте контекст (назву проекту або ідентифікатор запуску):
  ```typescript
  logger.info(`[${projectName}] Успішно зібрано соняшники`, { count: 20 });
  logger.error(`[${projectName}] Помилка кліку на елемент`, { selector, error });
  ```

## 🌿 Git Workflow та конвенції комітів

### 1. Стратегія гілок:
- `main` — стабільна гілка, готова до деплою на сервер.
- `feature/<назва>` — гілки для розробки нового функціоналу або нод.
- `fix/<назва>` — виправлення багів.

### 2. Формат повідомлень комітів (Conventional Commits):
Повідомлення мають бути чіткими та інформативними (рекомендовано українською мовою):
- `feat(nodes): додати ноду автоматичного поливу рослин`
- `fix(browser): усунути витік пам'яті при ротації скріншотів`
- `perf(cache): оптимізувати відповідь списку проектів через LRU кеш`
- `docs: оновити інструкцію з налаштування Camoufox`
- `refactor(engine): перевести обхід графа на асинхронний ітератор`

## 🧪 Запуск тестів та перевірок якості

Перед кожним комітом або створенням Pull Request обов'язково виконайте перевірку:

```bash
# 1. Перевірка компіляції та типізації бекенду
cd backend
npx tsc --noEmit

# 2. Запуск тестів бекенду
npm test

# 3. Перевірка збірки фронтенду
cd ../frontend
npm run build
```

## 🔄 Оновлення графа знань проекту (Graphify)

У проекті налаштовано аналізатор архітектури **Graphify**:
- Після додавання нових модулів, рефакторингу або зміни зв'язків між файлами виконайте команду:
  ```bash
  graphify update .
  ```
  Це оновить базу знань у каталозі `graphify-out/` без додаткових витрат API.
