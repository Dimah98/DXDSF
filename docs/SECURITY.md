# 🛡️ Політика безпеки та захисту даних (Security Policy)

Цей документ описує модель загроз, заходи захисту даних, політику ізоляції браузерів та інструкції щодо відповідального розкриття вразливостей платформи **Sunflower Land Bot**.

---

## 🔒 Модель загроз та архітектура захисту

Оскільки платформа взаємодіє з блокчейн-грою та може зберігати облікові записи, сесії гаманців Web3 та проксі, безпека реалізована на кількох рівнях:

```text
[ Мережевий рівень ]  ➡️  CORS Whitelisting, Helmet Security Headers, Rate Limiting
         ⬇
[ Рівень доступу ]    ➡️  JWT Токени (HS256), CSRF захист (x-csrf-token)
         ⬇
[ Шар додатку ]       ➡️  Валідація вхідних даних (Zod), централізований Error Handler
         ⬇
[ Ізоляція браузера ] ➡️  Camoufox Fingerprint Masking, ізольовані профілі /profiles
         ⬇
[ Збереження даних ]  ➡️  AES-256-GCM шифрування ключів, SQLite WAL, відсутність відкритих паролів
```

---

## 🦊 Антидетект та ізоляція через Camoufox

Платформа використовує рушій **Camoufox** (Firefox fork), спеціально оптимізований для обходу систем детекції ботів:
1. **Підміна апаратних відбитків (Fingerprinting):**
   - **Canvas & WebGL:** Генерація унікального, але консистентного для кожного профілю шуму.
   - **AudioContext:** Захист від аналізу аудіо-відбитків.
   - **Шрифти та розширення екрана:** Синхронізація з реальними системними профілями Windows/macOS.
   - **WebRTC Leaks:** Повне блокування витоку реальної IP-адреси повз налаштований проксі-сервер.
2. **Ізоляція профілів (`/profiles/<projectName>`):**
   - Кожен проект працює у власному окремому каталозі профілю браузера.
   - Сесії, IndexedDB, LocalStorage та кукі різних ферм ніколи не перетинаються.
   - Очищення тимчасових кешів виконується автоматично.

## 🔑 Управління секретами та ключами

### 1. Змінні оточення:
- **`JWT_SECRET`:** Використовується для підпису сесійних токенів. **Обов'язково** змінюйте дефолтне значення у продакшн-середовищі на випадковий рядок довжиною від 32 символів:
  ```bash
  openssl rand -base64 32
  ```
- **`ENCRYPTION_KEY`:** 32-байтовий ключ шифрування, який використовується для захисту збережених приватних ключів гаманців або паролів.

### 2. Приватні ключі Web3:
- Заборонено зберігати незашифровані приватні ключі гаманців або seed-фрази у відкритому вигляді у файлах `.json` або базі даних.
- Використовуйте підсистему `src/secrets/` або передавайте ключі безпосередньо у захищені профілі браузера (наприклад, через розширення MetaMask/Ronin у відповідному каталозі `/profiles`).

## 🌐 Захист мережі та API

1. **Обмеження походження (CORS):**
   - У `docker-compose.yml` змінна `ALLOWED_ORIGINS` визначає список дозволених доменів для підключення клієнтів (наприклад, `http://localhost:5173,https://yourdomain.com`).
   - Будь-які запити з неавторизованих доменів автоматично відхиляються з кодом `403 Forbidden`.

2. **Захист від підробки запитів (CSRF):**
   - Усі мутуючі маршрути REST API (`POST`, `PUT`, `DELETE`) вимагають передачі заголовка `x-csrf-token`, згенерованого бекендом під час ініціалізації сесії.

3. **Rate Limiting:**
   - Для критичних операцій масового запуску (`/api/projects/run-multiple`) діє ліміт частоти запитів для запобігання перевантаженню CPU та вичерпанню оперативної пам'яті.

## 📢 Повідомлення про вразливості (Vulnerability Reporting)

Якщо ви виявили вразливість безпеки в платформі Sunflower Land Bot, будь ласка, дотримуйтесь правил відповідального розголошення (Responsible Disclosure):

1. **Не створюйте публічні GitHub Issues** з описом експлойтів чи потенційних вразливостей.
2. Надішліть приватне повідомлення автору або зв'яжіться електронною поштою / через Telegram із детальним описом:
   - Кроки для відтворення вразливості.
   - Потенційний вплив (витік сесій, виконання довільного коду тощо).
   - Запропоновані заходи для усунення.
3. Ми прагнемо реагувати та надавати патчі безпеки у найкоротші терміни.
